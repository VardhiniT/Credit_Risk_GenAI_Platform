# Credit Risk Platform

A mortgage credit-risk scorecard built the way a lender would run it: cleaned data, a documented
feature contract, an explainable WOE scorecard, and (coming next) a Snowflake + dbt + Airflow
pipeline, monitoring, and a governed GenAI explanation layer.

**Status: Workstream A (model) done. B (Snowflake/dbt/Airflow), C (monitoring), D (GenAI) next.**

## Data (read this first)

- **Real:** Freddie Mac loan-level file, one origination vintage (Q1 1999), 291,451 loans.
  The model is trained and validated only on this.
- **Simulated:** monthly batches of new loans with controlled drift, generated by resampling real loans
  (`scripts/simulate_batches.py`). Used only to test the pipeline and monitoring, never to train.
  Because drift is injected by design, monitoring on it proves the machinery works; it is not drift observed in the real world.
- Real and simulated rows go through the same cleaning code (`src/credit_risk/data.py`).

## Quick start

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp /path/to/FreddieMac.csv data/raw/

make test        # unit tests
make train       # primary target: 3+ months delinquent
make train-ever  # sensitivity check: any delinquency
make simulate    # 24 monthly simulated batches + outcomes
```

(`make` just sets `PYTHONPATH=src`; the underlying commands are in the Makefile.)

## Feature contract (config/config.yaml)

| Item | Decision |
|---|---|
| Primary target | `serious_delinquency` = `MonthsDelinquent >= 3` (about 9.2% of loans) |
| Secondary target | `ever_delinquent` = `MonthsDelinquent >= 1` (about 19.8%) |
| Model inputs | 14 origination-time columns, plus 3 derived flags |
| Monitoring and fairness segments only | `PropertyState`, `MSA`, `SellerName`, vintage quarter |
| Excluded | `MonthsInRepayment` and `MonthsDelinquent` (leakage), `ServicerName` (assigned after origination), `OCLTV` (duplicate of LTV), `ProductType`, `OrigLoanTerm` (near-constant), `PostalCode` |

`config.yaml` also holds a guard: training fails if a forbidden column ever becomes a model input.

## Results on real data (primary target, held-out 30%)

| | AUC | Gini | KS |
|---|---|---|---|
| Test | 0.773 | 0.545 | 0.425 |
| 5-fold CV (binning refit inside each fold) | 0.775 +/- 0.003 | | |

Calibration is within 1.7 points in every PD decile. Risk bands are monotone (bad rate 29% in the riskiest
band down to 1.2% in the safest). Full detail in `artifacts/serious_delinquency/` including `model_card.md`.

Earlier notebooks reported higher AUC (0.745 on a 20% target) partly because they used `MonthsInRepayment`,
a leakage variable. See `notebooks/` for the original exploration.

## How it works

1. `data.py`: strip text, map `X` codes to `UNKNOWN`, treat 0 as unknown for CreditScore and DTI (with flags), build targets.
2. `woe.py`: WOE binning from scratch (monotone numeric bins, min 5% per bin, rare categories grouped).
3. `scorecard.py`: IV filter, correlation filter, logistic regression with a coefficient sign check, points table, reason codes, risk bands.
   Score = offset + factor * ln((1-PD)/PD), 600 points at 50:1 odds, 20 points to double the odds.
4. `evaluate.py`: AUC, Gini, KS, Brier, decile calibration, band table, PSI.
5. `train.py`: runs the above, saves artifacts and an auto-generated model card.

## Known limitations

- Single vintage: no out-of-time validation on real data.
- `MonthsDelinquent` is a count of late months, not a fixed-window "90+ days within 24 months" flag. Freddie Mac's monthly performance files would allow a proper one.
- No income, employment, bureau or macroeconomic variables in the dataset; none were invented.
- Fairness metrics by segment are planned but not yet computed.
